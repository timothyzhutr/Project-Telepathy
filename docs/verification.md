# Prototype release verification

## v0.2: one vision-language model

A pre-merge regression held window metadata delivery while screen hints were disabled, reproducing a screenshot starting after cancellation. Capture now rechecks the live session revision, deadline, permission and focus before requesting pixels. Tests exercise the production capture pipeline with only the system metadata/pixel operations replaced; a valid control still captures, while disable/re-enable, deactivation, word commit, timeout, same-app field movement, new text context and restricted fields prevent pixel capture. These tests do not record the desktop or cancel a screenshot already submitted to macOS.

The v0.2.6 update keeps capitalized words in an IME-owned marked composition rather than passing their first letter to the host. A physical check in the reporting app still showed the capital followed by Chinese candidates with v0.2.5, despite the earlier lifecycle fixtures passing. The expanded controller regression now requires the initial capital and subsequent letters to remain marked and uncommitted, with no candidate panel, before a single Space commit. The synthetic client also reports the caret inside marked text. Further cases cover Backspace, Escape without a stray committed capital, apostrophes, mixed case/keypad digits, punctuation, Return, Command shortcuts, lifecycle segment commits and genuine cursor moves. On 2026-10-17 the user confirmed that physical Shift+H, then `ello`, then Space in the affected app kept the whole word English with no Chinese candidates on installed v0.2.6. The installed executable matches the audited release build; its single model is ready and Screen Recording permission remains granted.

The v0.2.5 capitalization regressions reproduced two failures: a capitalized English word overwrote an established Chinese default for the next word, and a same-location IMK activation cleared literal passthrough midway through the word. Controller tests cover `Python` followed immediately by Chinese pinyin, both repeated activation and a full deactivate/reactivate cycle after `P`, and an actual cursor move that must still discard the temporary word override. The state regression preserves the prior definite language while allowing a first capital to seed English when no default exists. These tests exercise the production controller and Rime with a synthetic model boundary; physical-keyboard confirmation in the reporting host remains a separate check.

The v0.2.4 screenshot throttle uses one process-wide monotonic clock and permits at most one capture start per five seconds. A deterministic unit regression verifies shared claims, remaining cooldown and no accumulated burst allowance. Session regressions reproduced a second controller bypassing the cooldown before the integration fix; they now check shared throttling, cancelling a deferred capture after a word commit, a later eligible capture, and text-context revalidation before deferred work runs. Existing capture, stale-result, privacy and typing regressions remain part of the native suite.

The v0.2.3 native update retains the latest definite language decision across word commits and uncertain or failed replies. A selection tracker distinguishes host cursor/field changes from the IME's own commits, marked-text updates and passed-through keys. Unit regressions cover the retained default, explicit literal typing, selection changes, reused clients, and unavailable geometry. Controller regressions use real Rime and synthetic model/capture boundaries to check immediate English on a subsequent word, a prewarmed first letter, model failure, cursor relocation, and another empty field at the same text offset. No new model or continuous selection/screenshot polling is introduced. These fixtures do not establish selection-reporting reliability in every host application.

The packaged worker now uses one checksum-pinned Qwen3.5-0.8B-MLX-4bit checkpoint for continuation ranking, text routing and screenshot hints. Its setup manifest contains only the active vision model; weights remain outside the app. Reload and self-test regressions check that the previous model is released before another can load and that diagnostic runs honor the normal singleton lock.

Screen-language HTTP regressions reject malformed/truncated PNGs, invalid revisions, oversized bodies and images; a busy worker returns an uncertain hint without queueing another image. Image scoring uses disposable multimodal cache state. The packaged smoke test reads a synthetic English field, then verifies that the retained text cache still gives the same candidate order and a cache hit. Native snapshots remain usable without the model or screen permission.

Native state/session and real Rime/controller tests cover coalesced activation, bounded first-character capture retry, stale-focus and live restricted-client rejection before upload and acceptance, manual choices, text precedence, and late results after commit. A fixture English hint makes `a` followed by Space commit `a `; Down restores Chinese candidates. Blue-marker pixels and global-coordinate conversion are checked with a generated image, without capturing the user's desktop. Settings tests cover the screen toggle, permission action and migration to continuation-only ranking.

The v0.2.1 native update caches IMK’s unique client token rather than regenerating it during asynchronous capture. Regressions use a client whose token changes on every call, reject changed field anchors, and cover capture deadlines and late callbacks. Screen-hint status now exposes a bounded, sanitized history of stages and discard reasons, without text, window titles or screenshots.

The v0.2.2 icon regression renders the parent input-method icon and every mode icon at 1× and 2×, checking both visible ink and clear background. The prior package reproduced a solid-tile failure on the parent fallback (80/324 clear pixels at 18 px). Adding the parent icon mapping fixes that check while retaining the colored Finder app icon. A real Firefox focus capture also returned English in about 415 ms; the user’s physical-keyboard check committed `a ` as English.

Live menu verification on 2026-10-17: removing and re-adding the installed v0.2.2 input source still showed the old solid square. Quitting only `TextInputMenuAgent` through Activity Monitor let macOS relaunch it (PID 1182 → 36598); the user then confirmed the link logo appeared. No further app rebuild or input-source change was needed. The bundle-rendering test validates the asset and mappings, but does not detect an existing system menu process's stale image cache.

The package audit checks the unique transparent menu-icon resource, 73 active Rime/profile files, arm64 linkage and signatures, a vision-only download manifest, and the MLX library/shader layout. A root-level duplicate `libmlx.dylib` reproduced a packaged GPU import failure; the bundled root entries now link to the physical package libraries so MLX finds its colocated shader resource. The source environment and packaged executable are tested separately.

On the development Mac, the v0.2.1 installed executable matches the signed package and reports Screen Recording permission granted after refreshing the stale system entry. The previous ad-hoc signature used a per-build cdhash; the local build now uses a stable Apple Development identity. The source build supports an explicit signing identity or ignored local identity file.

Real empty-browser screenshots can still produce tied language scores even when the focused input is an address bar. Cropped-input probes performed better on the reported example, but no crop-based accuracy change is shipped in this update. Screen Recording permission and physical focus delivery are a separate live check. Unit fixtures and a synthetic image endpoint do not establish that every application reports activation or caret geometry correctly. No claim of full app coverage or a guaranteed first-keystroke deadline is made.

## Earlier releases

The native development input method was confirmed to accept physical keyboard input before packaging. The packaged v0.1.0 app and bundled worker were then installed from the release archive; the user confirmed Chinese input in Codex. The native information window added in v0.1.1 is checked separately from ranking and typing.

Package checks cover:

- Pinned and checksum-verified upstream assets and model-file manifest.
- Pruned Wanxiang profile: expected candidates for `nihao`, `butaixing`, `quanli`, `moxing`, and `zhongwen` in an isolated Rime session.
- A complete runtime inventory: no personal dictionaries, QA logs, alternate profiles, unused prediction plugin, updater framework, or neural weights.
- Apple Silicon Mach-O linkage, bundled binary minimum OS versions, strict/deep signature verification, and InputMethodKit controller class lookup.
- Relocated app path containing spaces, with no Python/Homebrew on PATH. Native CLI forwarding reaches the bundled Kev worker.
- Real offline inference with the pinned existing weights: consumer-rights context chooses `权利`, including a copied 12-candidate native snapshot, while preserving shorter-span candidates after the fully covered group.
- Missing-model native-order fallback and foreign HTTP origin rejection.
- Candidate coverage, stale-response rejection, manual selection freeze, partial composition mapping, model corruption detection, explicit downloader file/revision/credential controls, and installer rollback on a failed profile backup.
- The actual credits menu action opens a retained native window with readable credits and selectable license texts, without launching an external editor. Native regressions cover initial tab selection, bytecode/cache exclusion, unreadable-file handling, Copy/Select All/Close key equivalents, and closing/reopening one window. Copy's final action is intercepted in the test to preserve the user's clipboard.
- Lua's MIT notice is preserved as plain text with its source URL, without HTML markup or external resource loading. Package checks exclude Python cache files from the license directory.
- Native settings regressions exercise real AppKit control actions, persisted preferences, the actual TextKit candidate panel with 12 candidates arranged as four rows of three, saved font size, direct-tab model health, and scoped reset. Visual QA checks the preview, scrolling and controls in the native window. Health's HTTP boundary is stubbed in the UI regression; packaged worker health is checked separately.
- Model repair rejects a corrupt file even when its size and modification timestamp are unchanged, forces a fresh pinned download, and reuses other valid files without network access.
- Utility-panel presentation is checked against a separate covering application using real WindowServer ordering, with the activation request boundary forced to decline. The covering app raises its normal window again after Telepathy opens, reproducing a menu dismissal covering the settings window. The previous normal-window implementation fails this check; the floating, nonactivating panel stays above the host. The fixture exits if its parent test dies. This regression does not verify another app's full-screen Space.
- v0.1.8 helper lifecycle: a real subprocess stays absent with assistance disabled at startup, starts on enable, exits on disable, survives rapid off/on changes, and stops when its native owner shuts down without changing saved preferences. The same Swift controller fixture passes with the bundled worker and fully loaded pinned model in an isolated profile/port. HTTP shutdown also exits a real Python worker and releases its singleton lock.
- Upgrade handoff: a compiled legacy helper without a shutdown endpoint is stopped only at the old installed app's exact helper path. A differently located helper survives. The existing failed-backup rollback test remains passing.
- v0.1.9 ranking defaults: fresh and restored native settings select Context prediction; an explicit Kev selection persists when Settings reopens. Worker requests with an omitted strategy and the native CLI self-test use continuation scoring, while explicit `kev` requests use the decision head. Actual controller events forward the selected strategy. Packaged inference checks both methods, copied-context hits, shorter-span index mapping, empty-context native-order fallback and clean full-model process exit. Synthetic old/fresh accuracy and latency are documented separately in [the continuation comparison](../experiments/prediction/continuation.md).
- v0.1.10 candidate counts: real Settings actions independently save/reset ranking and display counts. Actual Rime/controller events rank 12 and render six, reject hidden number/click selection, clamp arrows, page through all remaining choices, handle one visible candidate and short final pages, and cross native page boundaries in both directions. Ranking three while showing six preserves the unranked suffix. Auto language routing retains all 12 candidates, and display paging also works with assistance off. Ranking-state checks reject malformed/late replies and verify visible-to-native selection mapping.
- v0.1.11 inference accent: actual controller events remove all model-status candidate text, distinguish scored choices from fallbacks, respect the accent toggle and retain ordinary highlights on unranked suffixes. Settings actions persist/reset the new toggle; hover-only redraws preserve metadata and new pages clear it. Native snapshots check the packaged light/dark themes and matching text colors. Worker checks distinguish valid/tied scores from no-context/nonfinite/single-choice fallbacks and map scored indices around shorter fragments. Packaged real inference verifies these flags for both rankers. Timing diagnostics remain in worker responses.
- Original artwork: the app and every visible input-mode icon reference the Telepathy ICNS/template PDF; stock Rime icons are absent. All ten ICNS sizes and template contrast at 16/18/22 points were visually checked. The README demo renders the production native candidate panel using a recorded synthetic request; replay reproduces its pixels.

v0.1.12 stability checks cover healthy orphan-worker reuse, clean lock-contention exits, delayed crash retries and cancellation on disable; HTTP errors versus transport failures; Unicode scalar limits and special-input bypass; atomic profile recovery with preserved custom files; and successful/failed/interrupted install backup retention. Actual controller events check Left/Right against displayed ranking, reject late overrides, and count real coverage probes to verify debounce, assistance-off and later-page bypasses. Instance-cache ownership and reload allocation checks prevent the old ranker from surviving replacement. The packaged worker is also reloaded with real pinned weights before inference is checked again.

The frozen 42-case and 44-case comparisons retained every candidate choice for both ranking methods in this update. The whitespace-only `fresh-40` language judgment changed from English to its labeled “uncertain” fallback. A local tokenizer microbenchmark for a 512-character Chinese passage reduced context trimming from about 35 ms to 0.22 ms, with identical retained text; this measures preprocessing, not end-to-end prediction latency.

The ranking smoke examples are synthetic and are not a quality benchmark. Packaged physical-keyboard activation on a fresh account remains a manual installation check. macOS input-source registration can require adding Telepathy in Keyboard settings and logging out/back in.
